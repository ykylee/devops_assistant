## 1. 문서 목적

본 문서는 프로젝트 진행 상황과 KPI 지표를 한눈에 관리할 수 있는 웹 시스템의 소프트웨어 요구사항을 정의한다. 현재 단계에서는 메인 페이지 중심의 화면 요구와 사용자 관점의 기능 요구를 구체화하며, KPI 세부 지표와 소스코드 품질 세부 지표는 추후 별도 요구사항으로 확장한다.

## 2. 시스템 개요

본 시스템은 여러 프로젝트의 진행 상황을 통합적으로 확인할 수 있는 웹 기반 대시보드이다. 사용자는 메인 페이지에서 전체 프로젝트 요약, 프로젝트별 현황, 테스트 현황, 소스코드 품질 현황, 개인 할 일, 경고 및 알림을 확인할 수 있어야 한다.

## 3. 이해관계자 및 사용자

| 구분 | 설명 |
| --- | --- |
| 관리자 | 전체 프로젝트 상태, 테스트 진행, 경고 항목을 종합적으로 모니터링하는 사용자 |
| 프로젝트 담당자 | 담당 프로젝트 현황과 이슈를 확인하는 사용자 |
| 일반 사용자 | 본인에게 할당된 할 일과 관련 알림을 확인하는 사용자 |

## 4. 전제 및 범위

### 4.1 전제

- 사용자는 시스템에 접속하여 본인 기준의 화면을 확인할 수 있다고 가정한다.
- 시스템은 여러 프로젝트의 진행 상태 정보를 수집하거나 제공받을 수 있다고 가정한다.
- KPI 지표와 소스코드 품질 지표의 상세 정의는 현재 범위에 포함하지 않는다.

### 4.2 현재 범위

- 메인 페이지 대시보드 요구사항 정의
- 탭 기반 현황 전환 요구 정의
- 소스코드 품질 현황 탭 요구 정의
- 사용자별 할 일 요약 요구 정의
- 경고 및 알림 표시 요구 정의

### 4.3 제외 범위

- KPI 산식 및 상세 지표 정의
- 소스코드 품질 측정 지표 정의
- 외부 시스템 연동 방식 정의
- 데이터베이스 및 내부 아키텍처 설계
- 화면별 세부 UI 스타일 설계

## 5. 기능 요구사항

### 5.1 메인 대시보드

| ID | 요구사항 |
| --- | --- |
| FR-001 | 시스템은 메인 페이지에서 전체 프로젝트의 요약 정보를 제공해야 한다. |
| FR-002 | 시스템은 메인 페이지에서 프로젝트별 진행 현황을 제공해야 한다. |
| FR-003 | 시스템은 메인 페이지에서 테스트 현황을 제공해야 한다. |
| FR-004 | 시스템은 메인 페이지에서 소스코드 품질 현황을 제공해야 한다. |
| FR-005 | 시스템은 메인 페이지에서 접속한 사용자의 할 일 요약을 제공해야 한다. |
| FR-006 | 시스템은 메인 페이지에서 경고 및 알림이 필요한 항목을 제공해야 한다. |

### 5.2 탭 전환

| ID | 요구사항 |
| --- | --- |
| FR-007 | 시스템은 프로젝트 요약, 프로젝트별 현황, 테스트 현황, 소스코드 품질을 탭 형태로 구분하여 제공해야 한다. |
| FR-008 | 사용자는 메인 페이지를 벗어나지 않고 탭을 전환하여 각 현황을 확인할 수 있어야 한다. |
| FR-009 | 시스템은 현재 선택된 탭을 명확히 식별할 수 있게 표시해야 한다. |

### 5.3 사용자 할 일 요약

| ID | 요구사항 |
| --- | --- |
| FR-010 | 시스템은 접속한 사용자 기준의 할 일 목록 또는 요약 정보를 제공해야 한다. |
| FR-011 | 사용자는 우선 확인이 필요한 업무를 메인 페이지에서 빠르게 식별할 수 있어야 한다. |

### 5.4 경고 및 알림

| ID | 요구사항 |
| --- | --- |
| FR-012 | 시스템은 진행 지연, 테스트 이상, 품질 저하, 확인 필요 항목 등 주의가 필요한 정보를 경고 또는 알림 형태로 표시해야 한다. |
| FR-013 | 경고 및 알림은 메인 페이지에서 눈에 띄는 위치에 제공되어야 한다. |

### 5.5 소스코드 품질 현황

| ID | 요구사항 |
| --- | --- |
| FR-014 | 시스템은 프로젝트별 소스코드 품질 상태를 탭 화면으로 제공해야 한다. |
| FR-015 | 사용자는 소스코드 품질 현황을 다른 주요 현황 탭과 동일한 수준에서 확인할 수 있어야 한다. |
| FR-016 | 시스템은 향후 소스코드 품질 지표가 확장되더라도 동일 탭 내에서 수용 가능해야 한다. |

## 6. 비기능 요구사항

| ID | 요구사항 |
| --- | --- |
| NFR-001 | 사용자는 메인 화면에서 주요 정보를 한눈에 파악할 수 있어야 한다. |
| NFR-002 | 메인 페이지의 정보 구조는 프로젝트 요약, 프로젝트 현황, 테스트 현황, 개인 할 일, 경고 영역이 명확히 구분되어야 한다. |
| NFR-003 | 메인 페이지의 정보 구조는 소스코드 품질 현황을 별도 탭으로 명확히 구분해야 한다. |
| NFR-004 | 탭 구조는 직관적이어야 하며 사용자가 현재 보고 있는 정보 범위를 쉽게 이해할 수 있어야 한다. |
| NFR-005 | 사용자별 할 일 정보는 접속 사용자 기준으로 개인화되어야 한다. |
| NFR-006 | 향후 KPI 지표와 소스코드 품질 지표 확장이 가능하도록 화면과 요구사항 구조가 확장 가능해야 한다. |

## 7. 화면 요구사항

### 7.1 메인 페이지 구성

메인 페이지는 다음 영역으로 구성되어야 한다.

1. 상단 헤더 영역
2. 현황 탭 영역
3. 탭 선택에 따라 변경되는 메인 현황 콘텐츠 영역
4. 사용자 할 일 요약 영역
5. 경고 및 알림 영역
6. 향후 KPI 및 품질 확장 영역

### 7.2 화면 동작 요구

| ID | 요구사항 |
| --- | --- |
| UI-001 | 사용자는 상단 또는 메인 영역에서 탭을 선택할 수 있어야 한다. |
| UI-002 | 탭 선택 시 대응하는 현황 데이터가 동일 페이지 내에서 전환되어야 한다. |
| UI-003 | 소스코드 품질 탭은 프로젝트 요약, 프로젝트별 현황, 테스트 현황과 동일 계층의 탭으로 제공되어야 한다. |
| UI-004 | 사용자 할 일 요약은 탭 전환과 무관하게 메인 페이지에서 지속적으로 확인 가능해야 한다. |
| UI-005 | 경고 및 알림 영역은 사용자가 메인 페이지 진입 시 즉시 확인 가능해야 한다. |

## 8. 사용자 시나리오

### 8.1 관리자 시나리오

1. 관리자는 메인 페이지에 접속한다.
2. 전체 프로젝트 요약을 확인한다.
3. 탭을 전환하여 프로젝트별 현황, 테스트 현황, 소스코드 품질 현황을 확인한다.
4. 경고 및 알림을 확인하여 우선 대응이 필요한 항목을 식별한다.

### 8.2 일반 사용자 시나리오

1. 사용자는 메인 페이지에 접속한다.
2. 본인에게 할당된 할 일 요약을 확인한다.
3. 관련 프로젝트의 현재 상태, 테스트 현황, 소스코드 품질 현황을 탭으로 전환하며 확인한다.
4. 본인과 연관된 경고 또는 알림을 확인한다.

## 9. 향후 확장 요구

- KPI 카드 또는 차트 영역 추가
- 소스코드 품질 세부 지표 카드 추가
- KPI 목표 대비 실적 표시
- 프로젝트별 상세 화면 연결
- 테스트 현황의 상세 drill-down 기능
