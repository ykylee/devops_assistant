## 1. 개요

본 과제의 목표는 프로젝트 진행 상황을 한눈에 관리하고 주요 KPI 지표를 확인할 수 있는 웹 시스템을 구축하는 것이다. 사용자는 메인 페이지를 통해 전체 프로젝트 현황과 개인 할 일, 테스트 상태, 소스코드 품질, 주의가 필요한 경고 및 알림을 빠르게 파악할 수 있어야 한다.

현재 단계에서는 화면 구성과 핵심 기능 방향을 우선 정의하며, KPI 지표의 상세 항목은 이후 별도 요구사항으로 추가한다. 단, KPI는 총 12개 항목이 표시될 예정이며 본 시스템의 주요 활용 목적 중 하나이므로 메인 화면에서 잘 보이도록 배치되어야 한다.

## 2. 과제 컨셉

- 전체 프로젝트의 진행 현황을 통합적으로 보여주는 관리용 웹을 제공한다.
- KPI 12개 항목을 한눈에 확인할 수 있는 시인성 높은 요약 영역을 제공한다.
- 조회 가능한 프로젝트 목록을 탐색할 수 있는 별도 화면을 제공한다.
- 프로젝트 단위의 상세 현황과 테스트 진행 상태를 함께 확인할 수 있도록 한다.
- 프로젝트별 소스코드 품질 상태를 메인 페이지에서 함께 확인할 수 있도록 한다.
- 각 프로젝트는 개별 상세 페이지를 가져야 하며, 사용자가 검색을 통해 바로 이동할 수 있도록 한다.
- 상단 네비게이션 바를 통해 주요 메뉴 간 이동이 가능해야 한다.
- 접속 사용자 기준의 개인 업무 요약을 제공하여 실행 우선순위를 빠르게 판단할 수 있도록 한다.
- 진행 중 경고 또는 알림이 필요한 항목을 메인 화면에서 즉시 식별할 수 있도록 한다.

## 3. 사용자 관점의 핵심 요구

- 사용자는 메인 페이지에서 관련된 전체 프로젝트의 요약 정보를 확인할 수 있어야 한다.
- 사용자는 메인 페이지에서 KPI 12개 항목을 잘 보이는 형태로 확인할 수 있어야 한다.
- 사용자는 조회 가능한 프로젝트 목록 화면에서 프로젝트들을 탐색할 수 있어야 한다.
- 사용자는 프로젝트별 현황을 구분하여 확인할 수 있어야 한다.
- 사용자는 테스트 현황을 별도 화면 성격으로 확인할 수 있어야 한다.
- 사용자는 소스코드 품질 현황을 별도 화면 성격으로 확인할 수 있어야 한다.
- 사용자는 상단 네비게이션 바를 통해 주요 화면으로 이동할 수 있어야 한다.
- 사용자는 상단 검색 창을 이용해 프로젝트를 검색하고 해당 프로젝트의 개별 상세 페이지로 이동할 수 있어야 한다.
- 사용자는 년도, 월, 팀, 그룹, 파트 기준으로 조회 범위를 조절할 수 있어야 한다.
- 사용자는 로그인 후 본인에게 할당되거나 확인이 필요한 할 일 요약을 확인할 수 있어야 한다.
- 사용자는 경고 또는 알림이 필요한 진행 이슈를 메인 페이지에서 확인할 수 있어야 한다.

## 4. 메인 페이지 요구사항

### 4.1 공통 구성

- 메인 페이지는 프로젝트 관리 현황을 종합적으로 보여주는 진입 화면이어야 한다.
- 메인 페이지 상단에는 네비게이션 바가 제공되어야 한다.
- 네비게이션 바에는 주요 메뉴 이동 기능과 프로젝트 검색 기능이 포함되어야 한다.
- 메인 페이지에는 다음 정보 영역이 포함되어야 한다.
  - KPI 요약 화면
  - 전체 프로젝트 요약 화면
  - 프로젝트별 현황 화면
  - 테스트 현황 화면
  - 소스코드 품질 화면
  - 접속 사용자 기준 할 일 요약
  - 경고 및 알림 표시 영역

### 4.2 탭 전환 요구

- 프로젝트 요약, 프로젝트별 현황, 테스트 현황, 소스코드 품질은 탭 형태로 전환하여 볼 수 있어야 한다.
- 사용자는 하나의 메인 페이지 내에서 탭을 전환하며 필요한 현황을 확인할 수 있어야 한다.

### 4.3 KPI 요구

- 메인 페이지에는 KPI 12개 항목을 표시하는 영역이 제공되어야 한다.
- KPI 영역은 사용자가 메인 페이지 진입 시 쉽게 인지할 수 있도록 높은 시인성으로 배치되어야 한다.
- KPI 12개 항목의 상세 정의는 추후 추가 요구사항으로 반영한다.

### 4.4 프로젝트 목록 및 상세 요구

- 시스템은 조회 가능한 프로젝트 목록을 보여주는 별도 화면을 제공해야 한다.
- 각 프로젝트는 개별 상세 페이지를 가져야 한다.
- 사용자는 프로젝트 목록 화면 또는 검색 기능을 통해 프로젝트 상세 페이지로 이동할 수 있어야 한다.

### 4.5 검색 및 필터 요구

- 상단 네비게이션 바에는 프로젝트 검색 창이 제공되어야 한다.
- 사용자는 검색어를 입력하여 원하는 프로젝트를 찾고 해당 프로젝트 상세 페이지로 이동할 수 있어야 한다.
- 사용자는 조회 범위를 조절하기 위한 필터를 사용할 수 있어야 한다.
- 필터는 년도, 월, 팀, 그룹, 파트 순으로 제공되는 것을 기본 방향으로 한다.

### 4.6 개인화 정보 요구

- 접속한 사용자 기준으로 할 일 요약이 제공되어야 한다.
- 개인 할 일 요약은 사용자가 우선적으로 확인해야 할 업무를 빠르게 파악할 수 있도록 구성되어야 한다.

### 4.7 경고 및 알림 요구

- 진행 상황 중 주의가 필요한 항목은 경고 또는 알림 형태로 표시되어야 한다.
- 경고 및 알림은 사용자가 즉시 인지할 수 있는 위치에 제공되어야 한다.

## 5. 범위 정의

### 5.1 현재 범위

- 프로젝트 진행 현황을 보여주는 메인 웹 화면 기획
- KPI 12개 항목 표시 영역과 배치 요구 정의
- 프로젝트 목록 화면 및 프로젝트 상세 페이지 요구 정의
- 상단 네비게이션 바, 검색, 필터 요구 정의
- 프로젝트 요약, 프로젝트별 현황, 테스트 현황, 소스코드 품질의 탭 기반 구성
- 사용자 할 일 요약 및 경고/알림 표시 요구 정의

### 5.2 향후 추가 예정 범위

- KPI 지표의 상세 항목 정의
- KPI 계산 기준 및 표시 방식 정의
- KPI 12개 항목의 세부 명칭과 우선순위 정의
- 소스코드 품질 지표의 상세 항목 정의
- 프로젝트 검색 결과 표시 방식 및 검색 정확도 기준 정의
- 필터 조건별 데이터 집계 기준 정의
- 각 화면별 상세 데이터 항목 및 상호작용 정의

## 6. 제약 및 전제

- 현재 단계는 요구사항 등록 단계이므로 상세 설계와 구현 내용은 포함하지 않는다.
- KPI 관련 세부 지표는 추후 추가 요구사항으로 반영한다.
- KPI 12개 항목의 상세 정의와 표현 방식은 추후 추가 요구사항으로 반영한다.
- 소스코드 품질의 세부 측정 기준과 지표 항목은 추후 추가 요구사항으로 반영한다.
- 검색 결과 정렬 방식과 필터 간 종속 규칙은 추후 추가 요구사항으로 반영한다.
